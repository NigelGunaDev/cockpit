## Keyboard and terminal behavior

The default cockpit leader is **Ctrl-]**; `--leader` selects one control key such as `C-a` or `C-]`. The cockpit refuses a leader matching the selected original session's prefix or secondary prefix; choose another leader rather than changing the original configuration. Only the private UI server uses that leader. Your original tmux prefix and configuration remain unchanged and pass through to the selected attachment.

Press **Ctrl+]**, release it, then press the shortcut key. While the leader is pending, the second top row turns yellow and shows **Cockpit shortcuts**, the configured leader and Sessions/Commands/Help keys when space allows. **Esc** cancels that pending shortcut and restores normal terminal input. This uses tmux's own per-client prefix state and cached escaped status text; it adds no polling loop or background service.

All other cockpit attachments stay read-only. Layout changes and resizing preserve view-only mode. A missing target stays disconnected; it is not replaced automatically by another task.

The sidebar starts collapsed, opens with keyboard focus and remains visible when selecting a terminal. Leader, `b` or its header's clickable **Esc Close** closes it and returns terminal focus. A sidebar that no longer fits is closed during small-window fallback. Opening a picker/history popup keeps the original task process alive. Selecting a session returns focus to its native terminal.

Sessions, Tasks/Create, Attention, Review, Git changes, both history views, Help and Commands share a one-row title header with a clickable **Esc Close** at the upper right (compact **Close** on narrow panels). Clicking Close always dismisses the whole panel, including during search or confirmation, without submitting a task operation or sending terminal input. Keyboard Escape keeps the panel's existing editing behavior: in session search it ends editing first, then another Escape closes. The shared header and selection styling live in `src/presentation.rs`; controls and status/errors remain in the panel's existing footer area.

Native tmux copy mode remains available through your original prefix. Cockpit history captures a bounded snapshot of the original pane and gives that panel its own scroll position; it does not put the original pane into copy mode. Alternate-screen applications may leave no earlier frames in tmux history, and capture cannot recreate them. Existing Claude transcript/log facilities remain the source for earlier conversation content.

Copy support depends on your terminal's clipboard capabilities and remains a manual validation item. The footer shows the highlighted terminal's full source paths, so projects with the same folder name remain distinguishable.

Bold session names, quieter metadata and a **›** marker identify the keyboard-highlighted row; text labels remain meaningful without colour. Narrow sidebars split selection/slot and input mode across separate lines so their meaning stays readable. ## Search commands and switch back

Press the configured leader, release it, then press **Space**. Type an action such as **history**, **create**, **split**, or **inbox**. Use arrows to select and Enter to run; Escape cancels. The menu shows the actual shortcut and explains basic missing prerequisites. The existing runtime checks current target identity, screen dimensions, and action eligibility again before execution. A command can still be refused when live evidence changes or a later CLI check fails; its error remains in the menu. The menu opens task forms/queues rather than submitting task creation, approval, or permission responses for you.

The controls guide, command menu, native global bindings, and `--help` use the built-in definitions in `src/commands.rs`. The leader remains configurable; individual action rebinding is deferred. Native bindings retain their existing behavior. Choosing another supporting panel hands the same popup to that panel; close it with Escape before using a different global shortcut. Typing in these panels never becomes task input.

Session search now accepts case-insensitive subsequences: **tkb** can find **task-b**. Exact field matches rank before substrings, then fuzzy matches; separate words can match different name/path/task/badge fields. Equal scores use deterministic full identities and paths. Search still preserves the highlighted identity when inventory changes, and Enter versus **a** retains its focus/replace versus add distinction.

Leader, **p** returns to the previous valid explicitly visited terminal. Visit A, then B, then use it to alternate between A and B. It reuses normal session selection, so an unpinned previous terminal replaces the focused tile and a pinned one is focused. The bounded recent list holds up to 20 identities in the current run; it is not saved across cockpit restarts. Refreshes, menu searches, and layout changes do not record visits. Missing, exited, or disconnected identities are skipped; a reused name is never accepted as the old target. With no valid previous terminal, the action explains why and does not select another task. Existing runtime failures leave input disabled until deliberately restored.

## Mouse, groups, and field focus

In the session picker/sidebar, click a terminal row to highlight it, then press **Enter** or click **Open terminal** to focus/replace; press **a** or click **Add to layout** to preserve other slots. A terminal-row click or double-click only selects; the separate action buttons use the same existing select/add behavior as Enter/`a`, including its input mode. They do not start a task or approve anything. Buttons are bound to the rendered terminal identity, rechecked before dispatch; a changed selection, missing/exited/disconnected target or group heading cannot attach through a stale button. Click a project/workspace heading to fold or expand it. **Tab/Shift+Tab** selects group headings; **Left/Right** folds/expands, and Enter on a heading toggles it. Up/Down still navigates terminal rows. Groups use full canonical project/workspace identities, so equal folder names remain separate. Folds last while that panel is open; closing/recreating it starts expanded. Search temporarily shows matching groups expanded and explains why folding is unavailable until the query is cleared. Folding never changes task attachment or input ownership.

Session, task, command, saved-history and review-task lists show a thin divider after each multiline record when the panel frame is at least **40 columns × 24 rows**. Smaller frames omit the dividers to preserve space. These are decorative rows, excluded from mouse selection; scrolled lists account for content and divider heights separately. Project/workspace headings retain their folding controls and improved selection contrast. Shared presentation is in `src/presentation.rs`, with separator-aware hit regions in `src/interaction.rs`.

The wheel moves through lists or scrolls the preview/details under the pointer. Inbox/queue task row clicks only select; they do not mark seen, acknowledge, resolve, approve, or start anything. The queue's separate clickable **View terminal** shortcut deliberately requests the existing VIEW-only task attachment; it grants no input or lifecycle authority. Saved-history row clicks read that record, Git row clicks read that file, and command-menu row clicks select a command for Enter. Mouse hit regions follow the rendered list offset and terminal size; an event against an outdated size is ignored. Existing keyboard controls remain available. Mouse reporting is enabled only for the supporting panel and restored on exit; physical Windows Terminal selection/clipboard behavior remains part of manual validation.

Register additional projects at launch with repeated `--project`. Clicking during confirmation returns to editing, except the header's **Esc Close**, which dismisses the form entirely and never launches creation. Enter still reviews, then a separate Enter confirms creation through the existing launcher; startup authorization is separate.

Leader plus an arrow navigates the actual visible native tile rectangles using the existing focus/control handoff. It does not select the sidebar, a hidden attachment, or wrap at an edge. Native grid position can differ from pin order. In focused layout there is no visible neighbor. The original terminal's mouse behavior and tmux prefix remain unchanged.

## Multi-session layouts and saved selections

Start by selecting a terminal. Open the picker with leader, `s`, move to another session and press **a** to add it. Repeat up to four times. Use leader, `2` for split, leader, `4` for grid, and leader, `1` for focus. A split shows the first two pinned tiles, substituting the selected tile when it is outside that pair. Focus uses native zoom when the sidebar is hidden. Hidden attachments remain alive and stop participating in original sizing; visible attachments participate in sizing, including inactive read-only tiles. There is one controlled tile per cockpit instance. Tiles attach whole native sessions; independent panes/windows within the same original session retain its shared layout/window behavior. The tested multi-terminal model uses distinct task sessions.

The first click in an inactive tile only focuses it. A subsequent click can reach the selected application. Leader, Tab changes focus without selecting a different original task. Enter on an unpinned picker entry replaces the selected tile; **a** adds it. Selecting an already pinned entry creates no duplicate client. Leader, `x` removes only its disposable attachment. Tasks are never auto-filled into a grid.

Layouts require at least 60 columns × 12 rows per private terminal container, plus split borders, pane headings and the cockpit's two status rows; original tmux status consumes its normal row. The sidebar uses 32 columns. A four-terminal grid therefore needs about 121 columns × 28 screen rows, or 154 columns with the sidebar. Larger dimensions are preferable for Claude. A requested layout that does not fit is refused with a reason. Shrinking an existing grid temporarily shows focus; enlarging restores the requested layout, preserving view/control mode.

Presentation preferences live in `${XDG_STATE_HOME:-$HOME/.local/state}/cc-cockpit/<socket-and-project-hash>.json`, owner-only, version 1. `--preferences /absolute/path/to/private-directory/workspace.json` overrides the file; its parent must be owner-only. These files contain validated target references, UI choices and optional logical `tile_registrations` for the separate session registry. They contain no task state. Corrupt/foreign files are left intact, and workflow state/config and run-manifest filenames are refused as preference targets. Concurrent cockpit instances have independent input focus; the last successful preference write wins for the same project/socket set. R2 may map a saved logical registration to its explicitly recovered native conversation, always Read only. An unrelated restarted/replaced session remains disconnected until explicitly selected. A stale selected tile never automatically redirects input to a different live task.

## Ownership, sizing and recovery

The original tmux server owns the agent processes and their workspaces. Each open cockpit owns a private, transient UI server and disposable attachment clients, with presentation preferences and the separate durable conversation inventory described below. Closing the cockpit disconnects those clients; it does not kill original sessions or agents.

Controlled attachment requires original `detach-on-destroy on`. Other policies are refused without changing your configuration. The cockpit validates observed target identity and disconnects on ordinary target loss or changed identity. A reused session name is never accepted as the previous target; validated native recovery can attach a new generation Read only. Concurrent changes to tmux exit behavior while attached are an unsupported case, as accepted in the implementation plan; observation is not an atomic input barrier against them.

Multiple clients share the original pane's geometry according to its existing tmux sizing policy. The cockpit does not promise independent terminal dimensions or change original sizing options. Other native clients may also provide input; cockpit control is not an exclusive lock over external tmux clients.

Reopen the application to attach surviving sessions after a terminal crash or normal detach. If the original processes are gone, enabled native registrations in the selected socket/project scope are recovered through the existing CLI. Missing workspace/native files, changed branches/repositories, occupied names or ambiguous ownership leave a visible error rather than creating a substitute task. The post-WSL-boot check covers two enabled Codex conversations; closed-session exclusion across reboot and the broader manual matrix below still require acceptance.

Presentation choices are saved at startup and after explicit cockpit actions. Shutdown does not save transient attachment loss over your last view/control choice. A reopened attachment must still pass generation and policy validation; a saved input-enabled preference never authorizes a replacement session.

## Remembered sessions

Press leader, **o**, or choose **Remembered sessions** in the command palette. The inventory shows live terminals and saved offline entries for the selected original tmux socket. Picker/sidebar badges distinguish remembered, forgotten, unverified, unregistered and unavailable-registry states. Use **↑/↓** to select, **r** to Remember/revalidate a live conversation, **l** to link an existing native session file, **f** to Forget, **t** to Retry restoration, **c** then a separate **Enter** to confirm Close terminal, **u** to refresh and **Esc** to close/cancel.

Actual connections attempt native identity registration: opening/adding a terminal, returning through the previous-session action, viewing a verified task terminal, attaching surviving saved tiles or the single initial target, and the uniquely identified terminal from successful cockpit task creation. Discovery, list rendering, highlighting and searching alone do not register anything. A connected terminal without sufficient native evidence stays pending and remains usable. Identity retries use the existing slow reconciliation tick, rather than scanning native stores on each draw or switch.

Native validation in `src/agents.rs` requires an existing same-user regular file, a recognized agent header, exact native ID and canonical cwd matching the terminal's cwd. It never chooses a conversation by newest modification time or cwd alone. Automatic identification uses these inputs:

| Agent | Evidence needed |
|---|---|
| Claude | Existing verified Claude session observation or explicit `--resume <ID>`/`-r <ID>`, plus the matching native `projects/<project>/<ID>.jsonl` file. `CLAUDE_CONFIG_DIR` from the agent process selects a custom state root. |
| Codex | An exact `codex resume <ID>` argument and matching native `sessions/.../rollout-<ID>.jsonl` metadata. `CODEX_HOME` from the agent process selects a custom state root. |
| Pi | An explicit `--session <absolute-file>` argument and a native session header with ID and matching cwd. |

An exact resume argument identifies the requested native conversation; it does not prove the agent loaded that conversation or passed a trust prompt. Agent-neutral inventory does not extend Claude task creation, attention/activity hooks or the saved-history reader to Codex/Pi.

External or newly started sessions without an exact discoverable conversation ID need an explicit link. Select the live terminal, press **l**, use **Tab** to choose Claude/Codex/Pi and type or paste the absolute existing native JSONL file path. **Enter reviews** its identity and target; a **separate Enter confirms** linking and remembering. Escape cancels. Exported conversation text cannot replace native resume storage; linking starts no process and creates no conversation. Native file lookup is bounded; missing or ambiguous evidence gives a reason and the explicit-file fallback. After switching Codex or Pi conversations inside the same process, relink the new native file. Existing verified Claude ID changes are reconciled automatically.

**Forget disables durable restore intent and leaves the agent running.** It also works for an offline registration. Ordinary reconnects do not undo Forget. Explicit Remember revalidates the saved native conversation and enables it again; a confirmed native-file link also enables it. If the agent or detectable conversation changed, relink first. **Remove tile** and **Detach** retain saved intent. Missing terminals remain offline entries; absence, native exit and task completion alone are not treated as an explicit closure.

**Close terminal** first shows the terminal name and exact native conversation ID. Check both before pressing Enter; Escape cancels. Confirmation durably forgets the registration before asking the installed CLI to terminate that exact original session. The CLI refuses changed targets, shared windows, multiple panes or unconfirmed native-file ownership. A refused/uncertain close stays forgotten: inspect the terminal and use native exit if appropriate; it will not reopen automatically. Closing a terminal is separate from task completion, worktree removal and Git merging. A popup Close/Escape merely closes that panel.

A closed terminal's saved layout slot can remain as a disconnected placeholder, including after reopening the cockpit. This is not a running or restored session. Select a live terminal explicitly with leader, **s**, or remove the old focused slot with leader, **x**; the forgotten conversation is not restarted by either action.

At interactive startup, `src/restore.rs` queues missing enabled registrations once through a transient sequential worker. It revalidates the installed project, existing workspace, Git common-directory generation, branch, native file and exact ID, then invokes `workspace recover`. The CLI reuses a uniquely matching foreground resume process or launches the saved agent with exact native arguments: Claude `--resume <ID>`, Codex `resume <ID> --no-daemon`, Pi `--session <file>`. It submits no prompt and bypasses no trust/permission setting. Each result/error is independent; uncertain launches retain their terminal for inspection, without blind respawning. **t** requests an explicit reconciliation/retry.

Requested native identity and loaded state are distinct. A matching resume argument can expose the requested terminal Read only while it is still at trust/loading. Only observing the exact process open the saved native file updates the durable runtime binding; even that observation does not prove model readiness. Recovery never restores input authorization. Enable control deliberately with leader, **v** after inspecting the terminal. Per-registration advisory locks serialize operations across cockpit instances; the existing tmux receipt reconciles a launch after interrupted/unknown outcomes. No database lock is held while starting an agent.

The installed Bash CLI wrapper preserves its entry `PATH` before Node/toolchain shims can rewrite it. Recovery resolves the agent there and keeps that PATH; it does not persist an executable path or depend on Volta. Native process lookup follows argv-preserving toolchain shims and the existing Node Codex wrapper to the native agent, retaining exact conversation and file-open checks and refusing mismatched or multiple native candidates. Mise-backed Codex recovery passed the recorded post-WSL-boot check; real post-fix Volta recovery remains untested. Export the environment you need before launching the cockpit; shell aliases themselves are not agent launch definitions.

The default store is `$XDG_STATE_HOME/cc-cockpit/sessions.sqlite3`, or `$HOME/.local/state/cc-cockpit/sessions.sqlite3` when `XDG_STATE_HOME` is unset. `--registry /absolute/path/to/private-directory/sessions.sqlite3` selects a dedicated store; the path must be absolute, and its directory/files must be private and owned by the current user. Symlinked storage and hard-linked files are refused. The inventory stores identity, native storage location, original terminal/boot evidence, optional repository evidence and enabled/forgotten intent, with a limit of 256 entries and an 8 MiB database safety bound. It stores no task authority or conversation contents. Logical registry references in preferences do not authorize a new runtime or restore input after a reboot.

`src/session_registry.rs` uses short advisory `flock` scopes and SQLite transactions for inventory updates; it holds no process-lifetime lock or daemon. Busy, corrupt, foreign or unsupported storage produces a visible registry error while live terminal use continues; corrupt/unsupported database bytes are left intact. `src/recovery.rs` owns the inventory controls and reconciliation; `src/restore.rs` delegates process operations, native validation and resume arguments to the installed workspace CLI. R2 adds no dependency or task state. Its two new process commands join the existing user-only hook guard outside bypass mode.

See session registry evidence for R1 checks and session recovery evidence for R2 checks. The initial real Codex production recovery check reached an unanswered trust prompt. The later shim and post-WSL-boot evidence records two exact saved Codex conversations reopened with mise, prior markers visible, native files open, new durable boot bindings and Read only attachments. A second launch reused the same processes without recovery jobs, and neither thread gained a model turn. Clean cockpit detach preserved both agents. A read-only Volta observation found the native process held its file open behind an untraversed shim; the initial explanation that Codex had closed the file was incorrect. Three new automated tests cover shim traversal, a mismatched child and multiple native children. Real post-fix Volta recovery, real Claude/Pi restoration, physical Windows Terminal, closed-session exclusion across reboot and a PC power cycle remain unverified. ## Saved conversations and logs

Leader, **Shift+H** opens saved history independently of terminal scrollback. The existing CLI reads native main-session transcripts for the selected project and its installed Git worktrees, plus retained exported conversation segments under their `sessions/logs/` directories. It does not export, start, resume or modify a session. A saved conversation remains readable without a live tmux session. After its native transcript or original worktree is gone, an export remains readable when retained under a discovered project/worktree root, for example by the existing workspace-removal workflow.

Use **↑/↓** or **j/k** for records, **Left/Right** to cycle registered projects, and **/** to filter the current project's records by task, workspace, session or source. Enter/Escape finishes filtering. **Tab** switches conversation/tool-event views. **f** searches the displayed preview; Enter/Escape finishes editing the query, **n/N** moves between matching lines, and a match beyond the visible columns is brought into view. **PageUp/PageDown**, **Home/End** and **h/l** scroll. **r** reloads the list and selected record. Escape closes the panel. Recorded task labels come from log evidence, independently of current task lifecycle state; ambiguous associations stay unknown.

Native records and saved exports are separate entries. Each read is a snapshot; partial JSONL, changed files, missing export parts and limits produce warnings. Read warnings also appear at the end of the scrollable content. Refresh refuses a replaced record identity and clears the old content until you explicitly select a current entry. An unsupported installed CLI gives an update diagnostic; it does not fall back to guessing a transcript path. Plain text is sanitized before rendering, and existing pattern masking is reused. Individual subagent-run drilldown remains available through the existing `sessions logs runs` and `show` CLI commands.

The additive CLI commands are:

```bash
sessions/bin/sessions logs history --json
sessions/bin/sessions logs history --record <listed-key> --json
```

Catalog/read responses use version 1, exact scoped record keys, source/workspace/recorded task/session metadata, and explicit `complete`/`warnings`. Worktree discovery reuses the existing read-only snapshot. After workspace discovery, the history catalog processes at most 64 storage roots and 4,096 directory entries, lists up to 256 records, reads at most 8 MiB/50,000 JSONL rows per input, and displays the first 256 KiB of each conversation/event preview. Exports read up to 64 conversation parts. Search covers only the loaded preview. Symlink storage/parts and unsafe manifest paths are refused. CLI calls retain the existing five-second/two-MiB subprocess bounds. Large records can remain incomplete; the viewer does not replace the full CLI/export files.

Projects need the updated installed `logs_commands.js` and new `history_reader.js`; update them through the normal reviewed framework installation after resync/merge. This feature does not update live project installations automatically. The isolated cockpit worktree's two installed API copies and installed-file manifest are synchronized without changing state, settings, config or hooks. See saved-history evidence.

## Read-only Git changes

Select a terminal and press leader, **g**. The panel reads the Git repository containing that terminal's current directory. It shows actual repository paths rather than guessing from task metadata. One panel covers one Git repository; consolidated multi-repository reviews and lifecycle review actions remain deferred.

Use **↑/↓** or **j/k** to select a file, **PageUp/PageDown** and **Home/End** to scroll the diff, and **h/l** or **Left/Right** to scroll horizontally. **Tab** switches working-tree and staged views. **r** refreshes; **Esc** closes. To inspect committed branch work, press **b**, enter an explicit local branch, tag or commit such as `main`, then Enter. The panel resolves its commit and merge-base and compares that base to the current working tree, including untracked files. It does not fetch or select a base automatically. A selected comparison remains pinned to its resolved base until you enter another one.

Working-tree mode compares tracked files with HEAD; before the first commit it previews current file contents instead. Staged mode shows the index diff, including before the first commit. Untracked files have bounded text previews; binary files show a summary, and symbolic links are shown without following them. Git reads use literal pathspecs, disable optional index locks, filesystem-monitor commands, external diff commands and text conversion, and never stage, revert, commit, fetch or approve anything. Filesystem snapshots are not transactional; refresh after an agent checkpoint.

The panel stays bound to the exact original terminal generation and repository identity, including the root/Git directory device and inode. Refresh refuses a replaced terminal or a different/recreated repository instead of following it. Original terminal processes keep running. Native tmux can dismiss a popup during underlying layout/focus changes: close the panel before switching terminals, then reopen it for the new selection.

Limits are visible: at most 256 listed files, 64 KiB untracked previews and 2 MiB per Git command, with a five-second command timeout. A larger diff produces an error rather than a silently complete result. Use Git directly for a fuller view. No new dependencies or review state are introduced. See recovery and Git changes evidence for executed tests and remaining manual checks.

## Task review workspace

Press leader, **Shift+R**, choose **Review task** in the command palette, or press **Shift+R** in the task queue. The review screen lists retained active and archived task artifacts from registered projects and worktrees. It does not require a live Claude terminal. An archived artifact retained in the main checkout can still be reviewed after its worktree is removed; deleted artifacts and logs cannot be reconstructed.

Use **1–4** for Overview, Changes, Verification and History. **Tab/Shift+Tab** cycles the task list, file/history list where present, and content. With Tasks focused, **Left/Right** changes project and **/** filters records; with entries/content focused, **/** searches displayed content and **n/N** moves between matching lines.
